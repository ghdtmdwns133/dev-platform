# Unity and Odin adapter

The adapter lets `devctl` validate a Unity project without a commercial
dependency in the repository.

## Integrity contract

`.devplatform/config.json` is the single source of truth for:

- `version` — required editor version, compared with
  `ProjectSettings/ProjectVersion.txt`.
- `scene`, `sceneGuid` — an optional protected scene and its GUID; `null`
  disables the scene check.
- `mainScene` — an optional scene that must stay the first enabled build scene;
  `null` disables the check.
- `requiredObjects` — optional scene file IDs, names, component class IDs and the
  global Volume flag that must survive edits (needs `scene`); `[]` disables it.
- `allowedScriptRoots` and `templateScripts` — optional folders new C# scripts
  must live under, plus exempt template scripts; `[]` allows scripts anywhere.
- `externalGuidBaseline` — package and built-in GUIDs that are not part of
  `Assets/`.
- `testPlatforms`, `buildTarget`, `odinEntryPoint` — execution defaults.
- `cloudBuild.target` — Unity Build Automation target id; required when the
  caller uses `unity-runner: uba` unless it passes `cloud-build-target`.

`devctl unity integrity --write-baseline` regenerates the external GUID
baseline from `Library/PackageCache`, `Assets/**/*.meta` and
`Packages/**/*.meta`. It refuses to run when `Library/PackageCache` is absent.

## Before the first verify

The generated config enables only the generic checks: required project paths,
the editor version, build-scene references, package JSON, `.meta` files, GUIDs
and references. Every project-specific protection rule starts disabled
(`null` or `[]`), so a new project is not bound to another project's scene,
objects or folder layout. Set `version` to the project's
`ProjectSettings/ProjectVersion.txt`, and opt in to the rules the project
actually wants: read the scene's `.meta` GUID, the scene YAML file IDs and the
enabled build scene before filling `scene`, `sceneGuid`, `mainScene` or
`requiredObjects`. New renders start with `testPlatforms: ["EditMode"]`; add
`PlayMode` only after verifying it on a machine with a GUI session. Renaming
the C# bridge namespace also requires updating `odinEntryPoint`.

## Odin bridge

The bridge consists of three files under `Assets/DevPlatform/Editor/`, in the
`DevPlatform.Editor` namespace:

- `OdinValidatorEntryPoint.cs` — static `Run()` entry point invoked with
  `-executeMethod`; writes the report and calls `EditorApplication.Exit`.
- `OdinValidationReport.cs` — serializable report DTO.
- `OdinValidatorAdapter.cs` — reflection-only detection of
  `Sirenix.OdinInspector.Editor.Validation.ValidationSession` and
  `ValidationProfile`.

No Sirenix assembly is referenced at compile time. When Odin is not installed
the bridge writes `{"status":"skipped","reason":"Odin Validator not detected"}`
and exits 0. With Odin installed it calls
`ValidateEverythingEnumerator(openClosedScenes: true, showProgressBar: false)`
and exits 1 when validation errors exist, 3 on exceptions.

`devctl unity odin` reads `artifacts/reports/unity/odin.json`. Add
`--require-odin` to turn `skipped` into exit code 4.

If a project sets `allowedScriptRoots`, include `Assets/DevPlatform/` in it or
list the bridge files in `templateScripts`. The `.meta` files are generated by a
batchmode import and committed next to the sources.
