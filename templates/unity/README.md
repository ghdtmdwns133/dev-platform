# __PROJECT_NAME__

Unity project configuration generated by
[dev-platform](https://github.com/__OWNER__/dev-platform).

This template is not a complete Unity project. Copy its files into an existing
Unity project at the repository root:

- `.devplatform/config.json` — Unity version, protected scene GUID, required
  objects, script roots and the Odin entry point.
- `.editorconfig` — C# style rules.
- `.github/workflows/ci.yml` and `nightly.yml` — shared platform workflows.

The Odin bridge sources are copied from `project-delta` by the integration
owner; see `docs/UNITY-ADAPTER.md`.

## Local verification

Integrity checks do not need an editor:

```bash
uv run --project .dev-platform/cli devctl verify --profile unity-assets
```

Full verification runs the EditMode and PlayMode suites, parses coverage and
optionally builds a player:

```bash
uv run --project .dev-platform/cli devctl verify --profile unity
uv run --project .dev-platform/cli devctl verify --profile unity --unity-build
```

## CI runner modes

`ci.yml` calls `unity.yml` with `unity-runner: none`, so CI runs only the
integrity gate. Set `unity-runner: self-hosted` on a repository with a runner
labeled `[self-hosted, windows, unity]` to run Unity on every
`Assets/**`, `Packages/**` or `ProjectSettings/**` change. `unity-runner:
gameci` keeps the GameCI implementation for accounts with a supported license.

Builds are opt-in through the `build` input and are meant for tags and nightly
runs.

## Release automation

`release-please-config.json` uses the `simple` strategy with `version.txt`.
The caller `.github/workflows/release.yml` runs release-please on pushes to
`main`; when a release is created, the same workflow runs
`devctl unity build` on `["self-hosted","windows","unity"]`, zips
`artifacts/unity-build` and attaches the zip to the release. Configure
`RELEASE_TOKEN` so release PRs trigger CI; see `docs/ADOPTION.md` and
`docs/UNITY-CI.md`.
